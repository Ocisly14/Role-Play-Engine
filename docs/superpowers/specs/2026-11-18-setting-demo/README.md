已用一次性脚本检查：
- 布景只引用固定件和出口，每个恰好一次，出口全部被引用；
- 没有物品既被引用又有 `placement`，每个非固定件都有 `placement`；
- `container` 都指向同一场景里的物品，没有成环；
- 迁移前被散文引用的物品，迁移后都是固定件或放在明面；
- 布景、物品、通道里没有 NPC 名字（不分大小写）。

## 新建的小物品

原来写在散文或物品描述里、会被单独拿起来用的小东西，建成了自己的物品：

| 场景 | 放在明面（只有 `placement`） | 装在容器里（`placement` + `container`） |
|---|---|---|
| 堂座 | 县报、钓鱼月刊（报纸架上） | 葡式蛋挞（玻璃点心柜，透明）；收银机里的现金、赊账纸条和旧账单（收银机抽屉，合着） |
| 后厨 | 老鱼刀（刀座里）、火柴（煤气灶边）、送货单（干货架铁钉上） | 冷柜里的食材（立式冷柜，关着、不透光） |
| 楼上 | 老花镜、止痛片（床头柜上）、矮烛台（圣母像脚边）、信纸和钢笔（来信旁）、裁缝剪（针线笸箩里） | 衣柜里的衣服（木衣柜，柜门合着） |

挑选标准（我的判断）：
- **会被单独拿走、使用或者有意义的，建成物品**：钱、刀、火柴、单据、药、剪刀、吃的。
- **跟着容器一起走的，留在容器的描述里**：小费罐里的零钱、糖罐里的糖。
- **只是背景、不太会单独拿的，留在固定件的描述里**：备菜台下面的盘子、干货架上的米袋、墙上的相片。有人去动它们时，Engine 再把它们建成物品。

**容器只描述它自己的状态。** 收银机抽屉、冷柜、衣柜里有什么，原来写在容器自己的描述里，渲染器会把它交给任何站在旁边的人，等于隔着柜门看见了里面。现在容器描述只写透不透明、开没开、开口朝哪（「推拉柜门朝着柜台里侧，此刻合着，四面玻璃」「抽屉朝柜台里侧开，此刻合着」），里面的东西各自建成物品，用 `placement` 说位置，用 `container` 指向容器。

**刀座、笸箩、报纸架不算容器**：它们挡不住里面的东西，所以老鱼刀、裁缝剪、县报只写 `placement`，直接算放在明面。

**装在容器里的东西看不看得见，每个人每一刻分别判断**，并在隐藏设计里「这一刻注意到了没有」那一步：依据容器的描述、这个人站在哪、在做什么。点心柜里的蛋挞几乎总会被看见；抽屉里的现金只有正在拉开抽屉的人才看得到。

## 做 demo 时发现、spec 还要补的

1. **容器里的东西（已定，已写进 spec）。** `placement` 只写位置，装在容器里的也写；`container` 指向装着它的物品；看不看得进去由容器自己的描述说明；看不看得见并入「注意到」那一步，渲染器只拿判成看得见的东西。要注意：这一步的开关 `DECISIONS_NOTICING` 现在默认是关的，关着的时候，点心柜里的蛋挞对谁都不可见（主动去翻、去开仍然有效）。
2. **人名还藏在物品名、物品 id 和通道描述里。** spec 只规定了布景和物品描述，要扩到物品名、id、通道的名字和描述。围裙的 id 在整个仓库里只被这两份场景文件引用，所以 demo 里直接改了。更大的问题在 spec 之外：schema 规定随身物品 id 写成 `item.<主人>.<东西>`，grayhaven 档案里有 53 个这样的 id。角色看到别人手里的东西，tag 就带着主人的名字。建议另开一项处理。
3. **出现了第一条「只给 Engine 的真相」。** 五斗柜底格锁着，这是物理事实，留在描述里；钥匙在 Dolores 围裙口袋里，是她的知识，挪进她的记忆。可钥匙并不是任何人身上的物品，有人要撬锁或找钥匙时，Engine 没有依据。spec 5.6 说先迁移完再数这类有多少，这里是第一例。
4. **固定件和道具的边界确实模糊。** 挂历、桌布、台灯、圣母像都拿不准。demo 按「日常会不会拿起来带走」来分：台灯、圣母像、桌布算道具，挂历算固定件。分错的代价不大，只影响挪动它时要不要改写布景。
5. **声音和视线的信息反而多了。** 原文借人物的习惯带出声学信息（Anita 偷听堂座、Dolores 在楼上听门铃），改写后变成地方本身的属性：「堂座里的说话声在后厨听得清清楚楚」「楼板不厚，楼下的动静听得见」。这对感知层更有用。
6. **迁移会顺带暴露原文的矛盾。** 楼上原文既写「单人铁架床」又写「床的另一半」，demo 去掉了「单人」。Anita 的记忆里后厨挂的是「门帘」，场景里却是弹簧门。
