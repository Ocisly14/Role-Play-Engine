# Tick Engine Refactor Design

## Date: 2026-03-09

## Summary

Restructure the tick engine to use a single-layer tick model (removing the tick/bucket duality), make impact a core engine concept, and give features configurable tick intervals.

## Core Concepts

### Tick

The minimum world simulation unit. Default 5 minutes of game time. A player action triggers N consecutive ticks. The last tick may be shorter than 5 minutes (uses remaining time) but does **not** count as a full tick for feature interval purposes.

### Impact (Engine Core)

Defined at the engine layer, not owned by any feature. Every PlanNode must include `impact: 0-5`, describing the spatial propagation range of the action:

- **0**: Private / unnoticed — only the acting character knows
- **1**: Targeted — only the specific target character perceives it
- **2**: Sub-scene / room-wide — everyone in the same room
- **3**: Building / macro-location-wide — everyone in the same building
- **4**: Neighborhood — nearby buildings within ≤15 min travel
- **5**: Global — entire game world

The engine provides a shared propagation utility (`findAffectedCharacters`, `findAffectedScenes`) that computes which characters/scenes fall within a given impact radius. Both the engine and features use this same utility.

### Feature (WorldFeature)

A world system plugin. Declares:

- `tickInterval: number` — how many full ticks between settlements (1 = every tick, 2 = every 10 min)
- `impactScope: number | "dynamic"` — spatial scope of this feature's effects (fixed value, or follows action's own impact level)
- `planningPrompt: string` — injected into LLM planning prompt (describes only the feature's effects, NOT impact levels)
- `stateDescription(dgsm)` — dynamic world state text for LLM context
- `onTickEnd(tickActions, dgsm, runtime)` — the single lifecycle hook, called at tick end

### NodeHandler

Unchanged. Executes a single PlanNode, returns a CharacterAction.

## Execution Flow

```
Player action (18 minutes) → 4 ticks (5+5+5+3)

Tick 1 (10:00-10:04, 5min):
  1. getDueNpcNodes(10:00, 10:04)       ← fetch per tick
  2. Merge with player nodes (gameTime in range)
  3. Sort by gameTime ASC, then DEX DESC
  4. Execute each node via handler.execute()
  5. Iterate features:
     - Increment counter (full tick)
     - If counter % tickInterval == 0 → call onTickEnd()
  6. Check playerEvents → pause if any

Tick 2 (10:05-10:09, 5min): same

Tick 3 (10:10-10:14, 5min): same

Tick 4 (10:15-10:17, 3min):
  1-4: same
  5. Less than 5 min → counter NOT incremented → features don't fire
  6. Advance gameTime
```

## Key Design Decisions

| Decision | Choice | Rationale |
|---|---|---|
| Player nodes placement | Distributed across ticks by gameTime | Nodes execute at their scheduled time, not all in tick 1 |
| Feature tick counter | Persists across player actions | Fire that started burning doesn't reset when player acts again |
| Partial tick counting | Does NOT count as full tick | Avoids feature firing on tiny time slices |
| NPC node fetching | Per tick | Allows revisePlans from previous tick to take effect immediately |
| Feature lifecycle hooks | `onTickEnd` only | Features react to results; no initialization needed |
| Player interrupt | Check at tick end | If playerEvents exist, pause remaining ticks and wait for player decision |

## Impact Propagation (Engine Layer)

```typescript
// Shared engine utility
function findAffectedCharacters(
  sourceLocation: string,
  impactLevel: number,
  dgsm: DynamicGameStateManager
): Map<string, number>  // characterId → perceived impact level

// Same utility used by features with their own impactScope
function findAffectedScenes(
  sourceLocation: string,
  impactScope: number,
  dgsm: DynamicGameStateManager
): string[]  // affected scene IDs
```

Feature examples:
- **ImpactGateFeature**: `impactScope: "dynamic"` (follows each action's own impact level)
- **FireFeature**: `impactScope: 3` (same building + adjacent scenes)
- **RainFeature**: `impactScope: 5` (global)

## WorldFeature Interface

```typescript
interface WorldFeature {
  id: string;
  description: string;
  tickInterval: number;
  impactScope: number | "dynamic";
  planningPrompt: string;
  stateDescription(dgsm: DynamicGameStateManager): string;
  onTickEnd(
    tickActions: CharacterAction[],
    dgsm: DynamicGameStateManager,
    runtime: TickRuntimeContext
  ): Promise<WorldFeatureResult>;
}
```

## Removed Concepts

- ~~Bucket~~ — replaced by tick
- ~~onTickStart~~ — not needed
- ~~onBucketEnd~~ — replaced by onTickEnd
- ~~conditionTypes~~ — replaced by impactScope

## Impact Prompt Ownership

Impact level descriptions (0-5) are generated by the engine/registry (`buildImpactPrompt()`), not by any feature. Features' `planningPrompt` only describes their own effects (e.g., "fire can spread to adjacent rooms").
